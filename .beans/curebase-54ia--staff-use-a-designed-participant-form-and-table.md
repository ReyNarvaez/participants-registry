## What to build

Replace the unstyled page with a designed one: Tailwind CSS, one centralized theme, and styled form fields, buttons, warnings, errors, the BMI filter, the participant table, paging and the loading overlay.

## Decision

UI library on top of Tailwind: shadcn/ui, recorded in ADR 002 › Styling and UI components. Options were:
- shadcn/ui (recommended): Radix-based, accessible components copied into the repo, themed by CSS variables
- daisyUI: Tailwind plugin with class-based components and themes
- hand-built components on plain Tailwind

## Acceptance criteria

- [x] Tailwind is set up in the frontend; theme tokens (colours, radius, spacing, typography) live in one place
- [x] Form fields, unit selects, buttons, field errors and soft-range warnings use the shared components
- [x] The participant table, BMI filter, paging and loading overlay are styled and readable on narrow screens
- [x] Accessibility kept: labels, focus rings, error announcements, aria-busy
- [x] Page-level tests still pass unchanged (they query by role and label, not by markup)

## Summary of Changes

- Tailwind CSS v4 (`@tailwindcss/vite`) and shadcn/ui 4.23 (Radix base, preset Nova, Lucide icons, Geist font) with the `@/` alias. Generated components in `src/components/ui/`: button, input, label, field, native-select, table, card, alert, separator.
- One theme, `src/index.css`: shadcn's tokens with the brand accent (clinical teal) on `primary` and `ring`. Components use tokens only.
- `components/Field.tsx` builds on shadcn's field and hands its control `id`, `aria-invalid` and `aria-describedby`, so label, error and invalid state are wired for every input in one place.
- Page: a header with the app name; a "New participant" card (two-column grid on wide screens, unit selects as styled native selects, success in a polite status region, failures as an alert); a "Participants" card with the BMI filter, a bordered table (numbers right-aligned and tabular, BMI bold), an empty state, a polite load-error alert and outline paging buttons. Narrow screens keep name, measurements and BMI as columns and show email, phone and birth date under the name. The not-found page is a card with a link back.
- Checked in a real browser (Playwright screenshots at 1280 and 390 px wide): default list, validation errors, a duplicate email from the seed, a filtered list on mobile, and not-found.
- The 20 page-level tests pass unchanged.
- Review findings declined: aligning the filter buttons without `sm:pt-6` (they can't wrap at sm and up); type-enforcing the Field render prop (a missing spread already fails label lookup in the tests). The unused dark and sidebar/chart tokens stay, as generated by the shadcn CLI; the theme comment says so.
